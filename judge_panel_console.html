判官团编排台

多采样择优（Best-of-N / Rejection Sampling）决策工具 —— 调参数、看良率、算成本、拿清单

先看这条，不然整个循环会空转

同 prompt + 同 seed + 同输入 → H3 的输出逐位相同（实测：音轨 PCM 完全一致，帧差仅 0.94–1.09/255，等于复现噪声）。 所以「不符合就重新生成」必须换 seed。照字面重提同一个任务，你只会花 N 倍算力拿到 N 份视觉上一样的片子， 判官也会给出 N 次一模一样的否决理由。

③ 判官团分诊表：7 类崩坏，哪些真能救

能救的共同点：失败是随机的（换 seed 就好）。救不了的共同点：失败是架构决定的（换 100 个 seed 只是崩的位置不同）。

判官 ≠ 闸门②的替代品

判官只能筛，不能修。去掉了动作白名单只装判官团，是最坏的组合：你会花 N 倍算力，反复确认同一件模型做不到的事。

④ 原子判据清单（直接喂给 L2 判官）

原则：check-before-score —— 先核验原子事实，再聚合分数；禁止开放式推理打分。R/W 类任一条「否」即否决。画面里本就不存在的检查项判 N/A 而非「否」。

末尾留了三行「本项目专属判据」，按你的品类补上。补的时候守住一个原则：判据必须绑定商业失效（产品 logo 变形 → 退货/客诉/合规；脸不像 → 信任度；音画不同步 → 完播率），不要写成美学偏好。

⑤ 落地顺序（顺序错了会白烧卡）

  1. 先建可复现性 —— 零 GPU，半天 每次生成必然记录 prompt 全文 / seed / 全部参数 / 参考素材 md5 / 输出路径（runs.jsonl）；重生成必然换 seed 并标 attempt_index；通过的 (prompt, seed) 对标记为资产。这一步防的就是开头那个空转陷阱。
  2. 搭 L0 + L1 —— 本地 CPU，零额外成本，1–2 天 六个 L1 检测器已经有现成脚本，只需包成统一的 judge_l1.py：输入 mp4 + 清单，输出逐项「是/否 + 数值 + 时间戳证据」。然后用历史人工判定样本标定每个检测器的阈值。
  3. 测 p，再决定要不要 L2 —— 用 ① 的表决策 同提示词连跑 8 个 seed，数几条通过判官，得到 p。p ≥ 0.5 → 上 N=3~5，一条 30s 只涨到 12–16 分钟，非常划算；0.2 ≤ p < 0.5 → 可用但必须分段冻结、坏段单独重跑；p < 0.2 → 止损，回闸门②改动作/改提示词/换工具，别加 N。

止损规则（硬性）

重试必须封顶 3–5 次，到顶就报明确失败，绝不静默续跑。一条片需要 5 次以上才过，说明是提示词错了或模型是错的工具 —— 再花钱也修不好。对一键成站尤其重要：一个用户提交了模型做不了的产品动作，无上限重试 = 无上限账单。

⭐ 第三条路，比修 B 类更聪明：让 B 类「不可验证化」

判据是「这个动作有没有可验证的物理结果」。反向利用它：不拍「涂开后皮肤变化」，改拍「产品静置特写 + 光影扫过 + 模特微笑」—— 没有任何一帧能验证消耗量，B 类崩坏就没有发生的舞台。判官的清单要同步把对应项判 N/A，否则会误杀合格的片子。
⚠️ 边界：把过程移出画面可以，但「暗示涂开后就有某功效」受广告法约束，那是另一条独立的合规线。这是设计问题不是生成问题，应该发生在分镜表（闸门②），成本几乎为 0。
