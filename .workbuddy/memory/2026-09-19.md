
## ClipForge 服务器端部署可行性核查（13:23–13:40）
- 起因：辉哥问「ClipForge 可以装在服务器端吗」。
- 实测（GHCR registry API）：官方镜像 `ghcr.io/xixihhhh/clipforge` 存在，222 个标签（113 版本 + 109 sha），版本到 **0.9.7**（与桌面版同版本）。
- 🔴 **关键发现：镜像仅 `linux/amd64`，无 arm64**（0.9.7 / 0.9.5 / latest 三个标签 manifest 均实测）。⇒ REPORT20 §5 第②步「Docker 起在本地 Mac」在 Apple Silicon 上会报 no matching manifest；Mac 只剩桌面版 dmg 或源码 pnpm dev 两条路。
- 🔴 **修正 REPORT20 红线1**：「CPU 争抢」理由被写宽了 —— FFmpeg 合成只在启用它自己的出片链路时发生，而我们明确不启用形态 C。仅用文字接口时它就是个空闲 Node 进程。
- ✅ **实测否认「内存不够」**：3090 容器 memory.max=90GiB / current=88GiB 但 anon 仅 28.7GiB，其余 58.5GiB 是可回收 page cache，零内存压力、0 次 OOM（REPORT22 §2）。加 0.5G 服务无压力。
- ⇒ **3090 仍否决**，但理由换成：共享机器纪律（跑着他人 heygem/tts-gateway 项目）+ 重启不回生 + LLM 不得指向 qwen3:14b + AutoDL 端口要开隧道（那不如跑本地）。
- ⇒ **独立 amd64 服务器可行**（1–2 核 / 2G 够），这才是一键视频网站后端的正确形态，但 AGPL-3.0 是先决条件。
- 产出：`REPORT36_ClipForge服务器端部署可行性核查_v1.0.md`（含修正后的部署清单，含锁版本建议）。
- 未测：a800 / hao 两台资源余量与 Docker 可用性；服务器端实际占用。
- 顺带踩坑：macOS 是 BSD grep，`grep "a\|b"` 这种 BRE 交替**不生效**（返回空）—— 本项目查文档一律用 Grep 工具或 `grep -E`。
